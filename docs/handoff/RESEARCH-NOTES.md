# Research Notes (Process step 1, 2026-10-02)

Key takeaways from the references in [ORIGINAL-BRIEF.md §8](ORIGINAL-BRIEF.md), plus a few targeted follow-up searches. Planning documents cite these sources.

| # | Source | Takeaways relevant to Rebuild |
|---|---|---|
| R1 | [1500 Archers on a 28.8 (Bettner & Terrano, AoE)](https://www.gamedeveloper.com/programming/1500-archers-on-a-28-8-network-programming-in-age-of-empires-and-beyond) | Turns of ~200 ms; commands issued in turn N execute in turn N+2. Host adapts turn length to slowest machine's frame time and RTT. UDP with own ordering/resend ("when in doubt, assume it dropped"). RTS players tolerate 250–500 ms command latency; *consistent* latency matters more than low latency. Heavy checksumming of world state, pathing and targeting to debug out-of-sync. |
| R2 | [Gaffer On Games — Deterministic Lockstep](https://gafferongames.com/post/deterministic_lockstep/) | Send inputs only; bandwidth independent of object count. Playout-delay buffer smooths jitter. TCP stalls under packet loss; use UDP and redundantly resend all unacknowledged inputs in every packet. |
| R3 | [Gaffer On Games — Floating Point Determinism](https://gafferongames.com/post/floating_point_determinism/) | Float results are not guaranteed identical across compilers, CPU architectures, optimization levels or debug/release builds. Fixed point sidesteps the problem. |
| R4 | [GDC 2024 — Pollard, Cross-Platform Determinism in *Realms of Ruin*](https://media.gdcvault.com/gdc2024/Slides/GDC+slide+presentations/Pollard_Bradley_CrossPlatformDeterminism+2024-03-26+09.34.19.pdf) | Shipped cross-platform lockstep using **fixed point** ("take the performance hit"). Floats blocked at compile time via reflection allow-list. Desync sources found: argument evaluation order (`f(Rand(), Rand())`), uninitialized padding bytes, type-size differences, RNG call order across systems (fix: per-system/derived RNG streams). Sim at 16 Hz, rendering interpolates. Server/host blames clients on desync; redundant retransmission instead of waiting for acks; command buffer grows under bad network, sim speeds up to shrink it. State-dump diff tool was critical. Replays come free with determinism. |
| R5 | [Godot docs — High-level multiplayer (stable = 4.7)](https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html) | `MultiplayerPeer` abstraction with ENet, WebRTC, WebSocket implementations; channels + transfer modes (reliable / unreliable / unreliable_ordered). No NAT traversal; direct hosting needs UDP port forwarding. RPCs are Node-bound — unsuitable for an engine-independent sim; use raw packets. |
| R6 | [ziva.sh — Godot multiplayer](https://ziva.sh/blogs/godot-multiplayer) | Godot lacks NAT traversal, lobby, matchmaking. Recommends GodotSteam for Steam relay + lobbies; Nakama as self-hosted backend alternative. Fits small sessions (2–8 players). |
| R7 | [Widelands (GitHub)](https://github.com/widelands/widelands) · [desync issue #6962](https://github.com/widelands/widelands/issues/6962) · [net relay issue](https://codeberg.org/wl/widelands/issues/3204) | Settlers-2-like open-source RTS, C++, **GPL v2+** (Rebuild is closed-source commercial → study ideas only, copy no code/assets). Lockstep with host ("NetHost"); periodic state checksums; "syncstream" files written by every peer and diffed offline to locate desyncs; has an internet relay server. (widelands.org returned HTTP 502 on 2026-10-02.) |
| R8 | [Kenney](https://kenney.nl) · e.g. [Retro Medieval Kit](https://kenney-assets.itch.io/retro-medieval-kit), [Medieval RTS](https://opengameart.org/content/medieval-rts-120), [Isometric Miniature Prototype](https://kenney.nl/assets/isometric-miniature-prototype) | All assets CC0 1.0 (commercial use, no attribution required). Both 2D isometric and low-poly 3D packs exist. |
| R9 | [Godot — C# platform support](https://godotengine.org/article/platform-state-in-csharp-for-godot-4-2/) · [C# docs](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/index.html) | Since Godot 4.2 C# exports to Windows, macOS, Linux; .NET 8 SDK; no web export for C# (not needed). |
